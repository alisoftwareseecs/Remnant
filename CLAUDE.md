# Remnant - project brief for Claude Code

2D psychological horror game. Built module by module; implement only the module you are asked for.

## Environment
- Unity 6000.3.2f1 (Unity 6.3 LTS), Universal 2D template (URP 2D renderer)
- Windows, PowerShell, Git + Git LFS
- Project root: D:\Unity\Remnant
- Input: Unity Input System package (the template's InputSystem_Actions asset). Do not use the old Input Manager.

## Folder conventions
All game content lives under Assets/_Remnant/:
- Scripts/ (subfolders per module, e.g. Scripts/Player/, Scripts/Story/)
- Scenes/, Prefabs/, Art/, Audio/, Data/ (ScriptableObjects)

C# namespace: Remnant (sub-namespaces per module, e.g. Remnant.Player).

## Rules
- Never edit or delete Library/, Temp/, Logs/, UserSettings/.
- Never create, edit or delete .meta files by hand. Unity generates them.
- Do not change ProjectSettings/ or Packages/manifest.json unless the task says so; if a package is needed, say which and why first.
- Prefer small, single-purpose MonoBehaviours and ScriptableObjects for data.
- Use [SerializeField] private fields, not public fields, for Inspector references.
- After each change, list exactly what the human must do in the Editor (create objects, assign references, layers/tags, scene setup), because you cannot click in the Editor.
- InputActionReference fields must point to actions inside Assets/InputSystem_Actions.inputactions, never to scene-local objects. After creating or editing a prefab, verify its input references are still assigned.
- Input action references (InputActionReference fields and InputSystemUIInputModule action slots) must be assigned as serialized asset references and verified after saving, never only through runtime API calls.
- Code must compile without warnings. The human will confirm by checking the Unity Console.
- Batch mode (Unity.exe -batchmode) cannot run while the project is open in the Editor. Ask the human to close the Editor first.

## Game design
- Setting: a school. Few maps, reused heavily; the player backtracks through the same areas, which can behave differently depending on story progress.
- Perspective has two modes:
  - SideView: left/right only, walk + run, NO jump. Doors and stairs via interaction.
  - TopDown: 8-direction walk + run. Used for puzzles, key findings and chase sequences.
- Perspective shifts are FIXED story events in specific areas, triggered narratively by the Shadow. The player never controls them.
- Time has two timelines: Present and Future. Time shifts are also fixed story events.
- Default mapping: Present = TopDown. Future = SideView, except Future puzzle rooms, which are TopDown.
- Perspective and time are SEPARATE systems. Code must keep them independent; any combination (SideView/TopDown x Present/Future) must work. The default mapping above is content, set by story events, never hard-coded.
- There is ONE ending (the good one), reached in the Present (Act 4). The storage-room reveal in Act 3 already showed what happens if you look away.
- Themes: guilt, silence, loss, blame and being unseen. The story involves a student's suicide; handle it with care. Abuse and the father's death are only ever mentioned in words, never shown.
- Backstory (revealed through the diary and the girls' taunts): Aiko's mother died giving birth to her. Her father blamed her, became an alcoholic and drug addict, and abused her. During one beating she pushed him away in self-defence; he fell, hit his head on concrete and died. The girls (Reina, Mika, Saki) call her "killer". She was blamed for two deaths that were not her fault.
- The game opens with a content warning.
- Art style: mixed packs for now (see Cast). Keep visuals swappable.

### Story
- Protagonist (player): a male student, name TBD. Aiko: a classmate who is bullied and depressed.
- Act 1, Present Day 1 (TopDown): a normal school day. The player sees the bullies tormenting Aiko and does nothing.
- Act 2, Present Day 2: Aiko is missing. The protagonist's Shadow awakens and leads him to the Future.
- Act 3, Future: a dark, changed school. SideView corridors where an unknown monster chases the player; puzzle rooms switch to TopDown through Shadow-triggered shifts. Clues lead to discovering that Aiko has hanged herself (a brief still image: rope and feet in silhouette, no gore).
- Act 4, back to the Present: the player tries to stop the bullying and finally sees Aiko. The monster was Aiko's ghost.
- The single ending: the protagonist finally sees her, stops the bullying and tells her it was not her fault; she lives and the monster is gone.

### The script (source of truth)
- `Docs/SCRIPT.md` is the source of truth for ALL dialogue, diary pages and Shadow captions. Use its text exactly; never rewrite, shorten or "improve" a line. Lines in (parentheses) are protagonist thoughts. A [TENSE] / [AUTO] / [NORMAL] marker applies to every line after it until the next marker or `##` heading; the default is NORMAL. `Tools/parse_script.py` parses it and `Tools/gen_dialogue_spec.py` turns it into the line list the `DialogueData` assets were filled from (it shows which block becomes which asset). When the script changes, change the matching asset(s) and the dialogue table `_previews/dialogue_lines.md`.
- The bullies are three girls: Reina (the leader, scene object `reina` / `reina_day2`), Mika (`mika`) and Saki (`saki`). The art sprites keep their file names `bully1_*` to `bully3_*` (Reina = bully 1, Mika = 2, Saki = 3). Speakers: Narration (no label), Protagonist (no label), Aiko, Reina, Mika, Saki, Shadow.
- The flashlight has no key: it is always on and aimed with the mouse (right stick on a gamepad); the script's hint line is "[Mouse] Aim the light".

### Act 3 details (as built)
- Route: Present_Classroom (Day 2 desk, the Shadow wakes) -> Future_Corridor (SideView, monster) -> door "2-B" -> Future_Classroom2B (TopDown, the ruined classroom, no monster) -> back door (opens after the diary) -> Storage_Hallway (SideView, no monster) -> the storage room -> back to Present_Classroom (Act 4, flag `act4`).
- The storage room: the old storage room at the far end of the ground-floor hallway behind classroom 2-B. The protagonist walked past it every day. It is where Aiko was locked in when the bullies got bored (the only place no one ever looked), and where she hanged herself.
- Aiko's diary (Docs/SCRIPT.md has the texts): eight dated pages in the Future 2-B classroom (flags `page_1` to `page_8`). Pages 1-7 are scattered and can be found in any order; the date is the header of the page panel (handwriting font GloriaHallelujah, the body shrinks to fit the paper) and each page can have a reaction thought that plays after that page closes (pages 1, 4, 5, 7). Page 8 lies on her desk (`DiaryPageInteractable` with `requiresFlags` page_1..page_7 and a `beforeDialogue`): the desk lines (blood, Tense) play first, then the page opens, then the Shadow's storage-room lines (its reaction) play and `diary_complete` is set, which unlocks the back door. A "Pages N/8" counter (pixel font, white, top-right, `DiaryController`) appears when 2-B is entered and disappears after page 8. The classroom's `DiaryUI` prefab is also used for the epilogue page (its counter is hidden there). The panel's "Press E to close" hint uses the pixel font like the dialogue box.
- Hangman on the chalkboard, drawn over three scenes: Day 1 only a head and four blank dashes; Day 2 head, body and arms; Future 2-B the full figure with the letters A I K O filled in ("The word was her name."). Each state is a chalk sprite shown by story flag.
- The cracked mirror (Future 2-B): one examination plays the whole scene (reflection, "Your shadow isn't in it.", the Shadow in Tense: it is not in the glass, it is in every second he did not look).
- The Shadow's true nature: it is the part of him that chose not to see. It is absent from mirrors, which foreshadows that it is the part of him that looks away. The Shadow must never be rendered in a reflection.
- The reveal (Storage_Hallway): only a tipped chair, a fallen shoe and her lower legs hanging from just above the knees (life size, one shoe on, one socked foot, toes down), with her cast shadow on the wall. Never her face or upper body, no gore, no rope or skirt on screen. An unlit black occluder drawn in front of the legs and the beam hides everything above the knees, so the flashlight can never reveal it. The beam has to touch her legs (same cone and line-of-sight test as the monster), then player movement and aim lock for about 4 s while the view cross-fades to a pixel-art close-up still (Art/Reveal/reveal_still.png, shown with point filtering) that stays up through the Shadow's lines. A slow fade then leads back to the Present with the title "Back." and the `act4` flag (the `day2` flag is cleared, so Aiko and the Day 1 girls are present). The reveal itself has no dialogue: the protagonist's thoughts and the Shadow speak after the still (Auto). Entering the hallway plays Tense thoughts (`storage_arrival`); the Shadow's Auto lines "during the slow walk" (`Storage_Walk_Shadow`, `lockPlayer` off, so the player keeps walking) start at x=4.5 (`storage_walk`), and the reveal waits until they are finished.
- Storage_Hallway has no monster, no running, and slower walking (set on its SceneSettings: Allow Running off, Walk Speed Multiplier 0.6). The hallway is 56 tiles long (the corridor was extended by 30 units before the storage-room end, so the walk to the reveal point takes about 30 s at the slow speed). `StorageWalkPacer` paces it to the Shadow's Auto lines: over the last third of the way the player's walk speed (`PlayerController.SetSpeedFactor`) eases down to distance-left / time-left, using `DialogueRunner.EstimatedRemainingSeconds` of the walk dialogue, so he arrives at the `RevealPoint` `arriveAfterLinesSeconds` (1 s) after the last line has faded (measured: the walk lines take about 32 s, the last one fades out at 32.8 s and he reaches the reveal point at 33.9 s; the natural, unpaced walk is 29.6 s, so the pacer slows him to about 0.7 of his speed over the last third); once the lines are done the speed is back to normal slow. He can never pass the `RevealPoint` while the lines are still playing (a position clamp that is only reached when his speed is almost nothing: his legs give out, there is no visible wall). Pacing is off in the daylight ending.

The Shadow's shouts are non-blocking captions (`EncounterHud`: pixel font, crimson, they type out and jitter; captions never queue, a new one replaces the one on screen at once): first appearance "Light! ### Dialogue system (Undertale-style box)
- ALL dialogue goes through the `DialogueBox` prefab (`Assets/_Remnant/Prefabs/UI/DialogueBox.prefab`, one instance per gameplay scene). Never build another dialogue UI; new dialogue is a `DialogueData` asset (Assets/_Remnant/Data/Dialogue) played with `DialogueRunner.Play(data, onDone)`. The content warning (chalk), credits, title and the diary page panel keep their own styling.
- Box: own Screen Space Overlay canvas (sort order 100), black box with a 6 px white border at the bottom (90% wide, 270 px of the 1080 reference), PixelOperatorMono TMP font asset (`Fonts/PixelOperatorMono Raster.asset`, sampling size 16 = native grid, hinted raster, point filter; used at 64 pt = 4x so it stays crisp), max 3 lines per page (longer lines are split into pages on word boundaries), blinking white triangle (continue indicator) only when a page is typed and the player may advance. Speaker names (Shadow, Aiko, Reina, Mika, Saki) are shown on a small tab on the box; Protagonist and Narration have none. Optional `* ` prefix: `starPrefix` toggle on the DialogueRunner (default off).
- Colour rule: only the Shadow is coloured (crimson #B0102A, `shadowColor` on the DialogueRunner); everyone else is white. Chosen automatically from the speaker.
- Every `DialogueLine` has a `DialogueMode`: Normal (~35 chars/s, short punctuation pauses, confirm skips the typing, confirm again advances), Tense (18 chars/s, comma and sentence pauses x1.33, ellipsis 0.4 s, every letter jitters 1-2 px re-rolled every 0.06 s by `JitterText`, confirm does NOT skip the typing, advance only when typed), Auto (hanging reveal and the Shadow's walk lines: all input ignored, 12 chars/s, pauses x3, ellipsis 1.35 s, no indicator, no blips; each page is held max(2.2 s, chars x 0.065 s), text fades 0.8 s, 0.5 s of silence, next line; the box fades in 1 s at the start and out at the end). All of these (and the base punctuation pauses: comma 0.14, sentence 0.28, dots inside an ellipsis 0.05, Normal ellipsis 0.45) are inspector values on the `DialogueRunner` in the DialogueBox prefab (tuning needs no code; the prefab's saved values are what counts, not the code defaults). Typing uses `maxVisibleCharacters`. `DialogueRunner.EstimatedRemainingSeconds` / `EstimateDurationSeconds` compute how long a dialogue takes from these same values (used by `StorageWalkPacer`); the estimate ignores the pause after a line's last letter, because the typewriter does not wait for it.
- Per-line colour fade: a `DialogueLine` can set `fadeColor` with `fadeFrom` and `fadeTo`; the whole text then changes smoothly (also between characters) from `fadeFrom` at the first character to `fadeTo` when the last one appears, overriding the speaker colour for that line; the speaker label keeps the speaker colour unless `fadeLabel` ("fade label too", default off) is set, then it fades in sync with the text. Used on "Your remnant." (crimson to white). Any line can use it; do not hard-code colours elsewhere.
- Inline tag `<shake>word</shake>` applies the Tense jitter to just those characters (stripped before display). Used on the girls' "killer(s)".
- Typing sounds: AudioSource + `defaultBlip` / `shadowBlip` clips on the prefab (empty for now; works silently), played every 2nd letter with pitch 0.95-1.05; none in Auto mode.
- `DialogueRunner.Play` queues a dialogue that is asked for while another is open (its callback still fires when its turn comes). `DialogueData.lockPlayer` (default on) can be switched off for dialogue that plays while the player keeps walking (the Shadow in the storage hallway). `DialogueRunner.CurrentDialogue` tells which dialogue is open (used by tests).
- `DialogueRunner.IsOpen` / `BlocksInteraction` lock the player and block interaction (also on the frame the box closes, so the closing press is not reused); the pause menu is blocked while it is open.
- Modes are defined by the script (see "The script" above), not by this file. The Act 4 encounter's shouted Shadow lines are non-blocking captions (`EncounterHud`, same pixel font, crimson, Tense jitter), not boxes, because the player must keep playing.

### Teardown safety
- `Remnant.Core.AppLifetime.IsTearingDown(gameObject)` is true while quitting, stopping Play mode or unloading the scene. `DialogueRunner.OnDisable` and `DiaryPanel.OnDisable` then close without running completion callbacks (the callbacks open panels, set flags or start sequences on objects that are already destroyed). Any new OnDisable that finishes work and fires callbacks must use the same guard.

### Mechanics
- Flashlight (Future, both perspectives): a URP 2D spot light aimed with the mouse or right stick (360 degrees in TopDown; in SideView the protagonist faces the side the beam points to). The Future is nearly dark, so the beam is the main light. Holding the beam on the monster for a short time banishes it (it fades out). It returns after a random delay, preferably from off-screen or behind the player.
- If the monster touches the player: game over, restart from the last checkpoint.
- The Shadow: the protagonist's own shadow, built in code from his current sprite (black silhouette, no eyes, unlit, slight distortion, delayed and sometimes out-of-sync movement). The monster keeps its white eyes and gets a faint cold tint, so the two never look alike.

## Architecture
- One central game state holds: current perspective, current timeline, story flags, recorded choices. Systems read it and react to its change events instead of polling.
- The player controller supports both perspective modes and switches when the game state changes.
- Each scene declares its perspective and time period with SceneSettings. Mid-scene shifts happen only through story events triggered by the Shadow. No player key ever changes perspective.

## Workflow
- Unity MCP (MCP for Unity v10.3.0) is connected on http://127.0.0.1:8081. Port 8080 is taken by another program (AgentService), so never switch back to 8080.
- Build and wire scenes directly with the Unity MCP tools: create GameObjects, add components, assign references, save the scene. Do not ask the human to do this by hand.
- Only if MCP is unavailable, fall back to an Editor setup script in Assets/_Remnant/Editor/ with a "Remnant/Setup/Module N - <name>" menu item (safe to run twice: reuse existing objects by name instead of duplicating them).
- Before any Editor change, check through MCP that Unity is not in Play mode. If it is, stop and ask the human to exit Play mode first.
- After writing code, wait for Unity to finish compiling, then read the Console through MCP and fix all errors and warnings yourself. Use %LOCALAPPDATA%\Unity\Editor\Editor.log only as a fallback.
- Runtime code never goes in an Editor folder; Editor code always does.
- The human's job is to press Play, test what you describe, and report how it feels.
- Before every commit, show git status. When the human confirms a module works, commit it as "Module N: <summary>".
